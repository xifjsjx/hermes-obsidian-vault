# Hermes 入库工作流细则

本文件在 SKILL.md 触发后按需读取，包含三类任务的完整操作步骤。

## 通用规范

### frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| title | 是 | 笔记标题，与 H1 一致 |
| type | 建议 | 概念 / 人物 / 工具 / 事件 / 摘录 / 清单 / 日记 / MOC |
| created | 是 | YYYY-MM-DD，脚本自动生成 |
| tags | 建议 | 3 个以内，用既有标签优先（先 `find` 看看库里怎么打的） |
| source | 可选 | 内容来源：chat / web / book / manual 等 |

### 命名与移动

- 文件名即标题，用自然语言，不加日期前缀（日期在 frontmatter）。
- 重命名/移动笔记后，用 `vault.py find` 找出所有指向旧标题的 wikilink 并逐个更新。
- wikilink 只写笔记名（`[[标题]]`），不写路径——Obsidian 按名解析，移动不断链。

## 任务一：信息入库（最高频）

触发：用户发来聊天记录、网页摘录、语音转写、截图文字或口述内容，要求"记到库里"。

1. **提炼**：把材料拆成独立主题单元，每个单元压出一句话核心结论。压不出结论的碎片不入库。
2. **查重**：每个单元执行 `vault.py find <vault> <关键词>`。
   - 已有同主题笔记 → 合并：补充新信息、更新 frontmatter，不新建。
   - 无相关笔记 → 新建。
3. **写入**：`vault.py new <vault> Notes/<主题>/<标题>.md --type <类型> --tags "..." --source <来源>`，正文按通用模板：一句话核心 → 要点 → 关联 wikilink（≥1 条）。
4. **登记**：`vault.py daily <vault> --text "- 入库：[[标题1]]、[[标题2]]"`
5. **回报**：新建 N 篇、合并 M 篇、舍弃 K 条（及原因）。

## 任务二：主题整理

触发："把 XX 相关的笔记整理一下"。

1. `vault.py find <vault> <主题词>` 捞出相关笔记，逐个通读。
2. 合并重复条目（保留信息最全的，其余内容并入后移入 `Archive/`）。
3. 补齐互链：同主题笔记之间应有 wikilink。
4. 若笔记数 ≥5 且无索引，建一篇 MOC 笔记到 `MOC/`，列出该主题笔记的结构化导航。
5. 回报：合并了几组、补了几条链、是否新建 MOC。

## 任务三：库级维护

触发："整理一下库" 或周期性保养。

1. **Inbox 清零**：`Inbox/` 内逐条分拣——提炼后入库、或直接移入 `Archive/`。
2. **孤立笔记**：`vault.py orphans <vault>` → 逐个处理：补 wikilink 接入网络，或归档。
3. **索引**：`vault.py index <vault>` 重建全库索引。
4. **回报格式**：`全库 X 篇；Inbox 已清零（入库 A / 归档 B）；孤立笔记 C 篇已处理；索引已重建。`

## 目录生长规则

- 某主题笔记满 5 篇才配单独子目录；不足时平铺在 `Notes/`。
- 子目录层级最多两层（`Notes/主题/笔记.md`），再深说明该主题该拆 MOC 了。
- 拿不准放哪的内容一律先 `Inbox/`，并在当日日记记一条待办。
